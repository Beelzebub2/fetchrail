# Contributing

## Branches

Use `<type>/<short-kebab-case-description>` for task branches:

- `fix/` for bug fixes and regressions.
- `feat/` for new features.
- `perf/` for performance improvements.
- `docs/` for documentation.
- `refactor/` for restructuring without changing behavior.
- `test/` for test changes.
- `ci/` for continuous integration.
- `chore/` for maintenance and tooling.

Choose the primary purpose for mixed changes. Keep `main` as the integration
branch and preserve unrelated work when preparing a change.

## Commits and pull requests

Use the configured contributor Git identity. Describe the problem, resulting
behavior and verified checks directly. Keep private investigation notes,
credentials and machine-specific details outside the repository.

Preserve legitimate contributor credits and required third-party notices.
