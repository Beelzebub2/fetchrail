Fetchrail privacy policy

Last updated: 19 October 2026.

RRMTools, Portugal, is the Fetchrail project operator responsible for optional analytics (the data controller). Privacy contact: support.fetchrail@rrmtools.uk.

Fetchrail Browser Integration connects your browser to the Fetchrail download manager installed on your Windows or Linux computer. It processes the information needed to select, route and control downloads. The desktop app separately offers optional improvement analytics with user consent, described below.

Information processed

  • Downloads: file URLs, referring page URLs, filenames, file sizes, content types, progress and the transfer options you choose.
  • Page content: when you choose “This page” or a page batch, the extension reads relevant links, media URLs, labels and download controls on those pages.
  • Browsing activity: with optional website access, the extension temporarily observes HTTP(S) request URLs, request methods and tab identifiers to associate a file request with its download page, including redirects and popups. It does not sell or use browsing activity for advertising.
  • Authentication information: only when you explicitly enable “Use browser session for captured files”, the extension may capture the final request's Cookie, Authorization, Referer and User-Agent headers to let Fetchrail download a file using your existing website session.
  • Local preferences: routing choices, session support, queues, connection counts, speed limits, schedules and page-batch state.

Where information goes

The extension passes download requests and transfer controls to the local Fetchrail app through Chrome's native messaging API. Fetchrail contacts the file server you select to verify and download the file. When browser session support is enabled, the relevant session headers accompany that file request. File servers receive normal network-request information, including your IP address, and apply their own privacy policies.

The developer does not receive your download history, page content, browser session headers or local preferences. The extension does not load remotely hosted executable code. Optional desktop analytics are described below.

Optional desktop performance calibration

The desktop app offers user-started hardware and connection tests with explicit network-data and temporary-disk budgets. Generated online traffic goes to Cloudflare's speed-test endpoints. You may explicitly provide a direct file URL for bounded ranged reads instead; that link is held in memory during the test and excluded from saved/copied reports. The chosen server receives ordinary request information including your IP address. Downloaded files, browser credentials and measurement reports are not submitted. Measurements and hashed network, volume and host tuning keys stay in the private local performance.json file, bounded to four reports, 128 observations and 2 MiB. Tuning expires after 14 days or relevant engine, network or volume changes. You can reset this data or disable automatic tuning in Settings > Performance. No additional browser permissions are needed.

Storage and retention

Preferences and page-batch state are stored in local browser extension storage. Temporary request observations use browser session storage, are bounded in size and are ignored after two minutes. Disabling browser session support clears the captured request observations.

Private-window request observations are kept separately in extension memory, never written to shared browser storage, and cleared when their tab closes. They expire after two minutes and are discarded if the extension restarts. Accepted private downloads appear in the desktop application's local history and follow the desktop retention rules below.

With session support enabled, right-clicked links and links pasted into the companion open in the chosen browser window before capture. Private browser batches stay in extension memory. Desktop links submitted with Use browser session wait in desktop memory for up to 15 minutes or until the app closes. Connected companions see only pending request identifiers and counts until you choose Use this window, which passes those links and download options to that browser for processing.

Fetchrail stores download history and unfinished-transfer details locally. If you enable session support, unfinished downloads may include sensitive session headers in the desktop app's local downloads.json file so they can resume after a restart. These headers are removed when the transfer completes or is removed. They are excluded from the extension's transfer status responses and the app's interface events. Downloaded files remain on your computer until you delete them.

Your choices

You can disable automatic download routing, leave browser session support off, revoke optional website access in your browser, stop a page batch, remove downloads from Fetchrail or uninstall the extension. Session support is off by default. Page scanning uses temporary access to the active tab after your action; broader HTTP(S) website access is optional and requested for page batches or session support. Private/incognito downloads can be captured only after you allow this extension in private windows through your browser's extension settings. Session forwarding still requires enabling Use my browser session.

Limited use

Fetchrail Browser Integration's use of information received from browser APIs complies with the Chrome Web Store User Data Policy, including the Limited Use requirements. Information is used only to provide the extension's download-management features. It is not sold, used for advertising, used to determine creditworthiness or provided to data brokers.

Optional desktop improvement analytics

RRMTools, the Fetchrail maintainer, offers optional first-party analytics to improve download reliability and prioritize useful features. It is off by default, including for existing installations, until you choose Allow in the desktop app. No thanks or closing the prompt keeps it off, with every feature still available. Settings → Privacy lets you allow or withdraw at any time. A changed collection scope requires a new choice.

Reports contain only the app release version, broad operating system (Windows, Linux or other), CPU architecture (x64, arm64 or other), and combined counts: app launches; HTTP/torrent downloads added, completed, failed or cancelled; pause/resume, speed limits, queues, schedules, browser handoffs and batch use. Completed transfers contribute a size bucket (below 10 MiB, 10 MiB to below 1 GiB, or 1 GiB and above). Only newly added transfers while consent is enabled are eligible; their first terminal outcome is counted once. There is no history import.

Analytics excludes URLs/domains, magnets, filenames/paths, browser history, cookies, credentials, request headers, raw errors, tracker/peer information, exact event times, user/device/session/transfer identifiers and detailed machine specifications. With consent, the desktop app may count a download handed off by the extension only under the desktop consent choice; none of the download or browser information listed earlier is included.

Counters stay in memory and are sent at most every 30 minutes to https://fetchrail.rrmtools.uk/api/analytics, operated by RRMTools on Cloudflare. Unsent counts are discarded on withdrawal, exit or failed delivery. Our service aggregates immediately into protected daily totals and does not store raw reports or IP addresses. Live aggregates cover the latest 30 UTC calendar days; Cloudflare's recovery copies may retain deleted aggregate data for another 30 days. Automatic invocation logging and tracing are disabled for this service; explicit release-service logs contain only operational release data.

Cloudflare necessarily sees your IP address in transit and may process network/security metadata under its own policies. These analytics minimize data and do not promise absolute anonymity. The optional analytics are limited to combined counters and do not add advertising, cross-service linking or unique-user tracking. Once combined into totals, individual contributions cannot be identified for deletion. App update checks and visits to the website are separate from desktop analytics.

Diagnostics and separate per-run sharing

Settings → Diagnostics runs only after your action. Processor, drive and memory results stay on your computer in the latest local diagnostic report. The optional connection checkbox sends bounded HTTPS download requests to speed.cloudflare.com, with at most 128 MiB of requested payload plus protocol overhead. Cloudflare receives ordinary request/IP metadata under its own policies. Fetchrail sends no uploads or diagnostic result reports to that speed-test endpoint; turn the checkbox off for a local-only run.

The existing usage-analytics choice does not authorize diagnostic performance fields. A completed release-build report offers a separate optional preview and Share choice covering that run only. The preview contains app release version, broad OS/CPU architecture and independent coarse processor, drive, memory and connection band counters. Exact measurements, available RAM, allocation size, model names, paths, endpoints, identifiers, error strings, timestamps and the full report are excluded. Grades are provisional synthetic bands, not universal hardware rankings.

Only an explicit per-run Share sends that summary to the RRMTools Fetchrail endpoint on Cloudflare. Keep local sends nothing and changes no functionality. Sharing can be cancelled while pending; there is no automatic retry or queue. A local attempt marker prevents duplicate shares, including after restart. The same protected daily aggregation, thirty-calendar-day live retention and additional up-to-thirty-day Cloudflare recovery window described above apply. No raw per-run summary, identifiers or IPs are stored by our analytics code; Cloudflare sees the IP in transit. Once combined, a contribution cannot be identified for deletion.

Website and support

This policy describes the browser extension, local desktop integration and optional desktop analytics. The Fetchrail website is hosted by Cloudflare, which may process ordinary website request logs and aggregate website analytics. Those website visits do not transmit your extension download history or session headers. GitHub handles visits, software downloads and support issues under its own policies.

For questions or requests, email support.fetchrail@rrmtools.uk or contact the maintainer through GitHub. Do not include private download URLs, cookies or credentials in public issues.

Legal basis and your data protection rights

Optional desktop analytics and per-run summary sharing rely on your consent. You may withdraw at any time without affecting the lawfulness of earlier processing. Refusal changes no download functionality. Local operational information is used to carry out the download and troubleshooting operations you request; optional saved crash breadcrumbs require their own choice.

Contact the privacy address to request access, correction, erasure, restriction or portability where applicable, or to object where applicable. Requests are normally answered within one month; a permitted extension must be explained within that first month. We do not introduce tracking identifiers to find an unidentified contribution after aggregation. We will explain that limitation and assist with local controls without demanding unnecessary identity information.

You may complain to the Portuguese data protection authority, CNPD, or your competent supervisory authority. CNPD also explains your rights and how to exercise them.

Desktop reliability diagnostics and separate optional analytics

Desktop version 0.8.2 introduces private local download health: bounded numeric stage and range-attempt timelines, body delivery windows, caps, checkpoint and verified-output counters, cause categories, broad software release/platform and safe torrent observations. Detailed native messages, source URLs, filenames/paths, credentials, tracker/peer addresses and infohashes are excluded from safe reports. These observations cannot prove the internal cause of delays in a server, ISP, storage driver or antivirus service.

Imports and browser verification/commit operations have separate local reports even when no download was admitted. The latest 20 remain in memory for the session and never enter routine fleet download counts. They contain no source strings.

Optional local crash breadcrumbs need a separate choice and are off by default. Windows account encryption or private Linux permissions protect up to 20 reports / 512 KiB. Seven-day expiry runs at startup, inspection and periodic cleanup; a closed app cleans files at its next start. Clear deletes owned diagnostic history; unrelated or damaged files are preserved with an error for manual inspection. A hard exit can lose unsaved evidence.

Copy/export of an incident requires a separate preview and affirmative review for that incident, independent of both analytics switches. No automatic incident submission or remote incident store exists. Exported files remain until you delete them. Agree a private recipient and retention before sharing; GitHub issues are public.

Existing product-improvement-v1 consent never enables product-quality-v2. The proposed independent scope contains only combined admission/outcome/size/error/protocol counters and fixed eight-bucket stage-duration histograms plus public release and broad OS/architecture. Only newly admitted transfers in the consent period qualify, with no backfill, source inspection, identifiers or persistent retry queue. Stage worker durations can overlap and are not network speed or additive wall time. Preview shows actual fields. Withdrawal stops collection, clears unsent counts and cancels pending requests; already received contributions cannot be recalled from combined totals.

The recipient remains Fetchrail/RRMTools through Cloudflare. Daily aggregates cover 30 UTC days, with provider recovery copies potentially another 30. Small v2 groups are suppressed below five report batches, not five people. Public intake can be forged; statistics are voluntary incomplete observations. Cloudflare sees transport/IP metadata; EU-only processing and absolute anonymity are not promised. From desktop 0.8.2, expanded analytics remains off until you expressly allow the separate product-quality-v2 purpose under notice reliability-v2-20261019. Earlier improvement grants and draft reliability choices do not enable it. Downloads work with either or both switches off; the companion gains no telemetry or permissions.

To protect the analytics intake from abuse, Cloudflare uses a temporary IP-derived rate-limiting key. Fetchrail does not copy that key into analytics tables, reports or application logs. This security processing relies on our legitimate interest in protecting the availability and security of Fetchrail; it is separate from consent-based product analytics. You can contact the privacy address to object where applicable. Cloudflare's network/security metadata follows the purpose, sensitivity, security and legal retention criteria in its privacy policy, rather than Fetchrail's aggregate deletion schedule.
