Resume an interrupted download with Fetchrail

A dropped connection does not always mean starting over. Fetchrail saves partial transfer progress, then checks the server before reusing those bytes.

Resume a paused transfer

  1. Open Fetchrail and locate the transfer in your download list. After the app closes during a transfer, it returns paused on the next launch.
  2. Keep the partial download files in their original location. Restore your network connection and select Resume.
  3. Expand the download row or open More → Download progress to inspect resume support, speed and individual connections.

Why a download can restart from zero

Resume probes the URL again. Fetchrail reuses saved partial files only when their range layout, total length and strong ETag or Last-Modified validator still match. A changed or unverifiable file representation restarts safely. This prevents joining bytes from two different versions of a file.

If the server ignores byte-range requests, Fetchrail falls back to a single stream. Non-range streams restart from zero after interruption. Transient range-transfer errors retry the affected segment from its saved offset while healthy connections continue; permanent errors can stop the whole transfer.

Expired links and logged-in downloads

A server may expire a URL or session while a transfer is paused. Sign in to the website again and obtain a current permitted file link if necessary. The browser companion has an optional Use browser session for captured files setting for downloads requiring authentication. Do not share private links, cookies or Authorization headers in public support issues.

Schedules and speed limits

Queue stop times pause network transfers while keeping partial bytes. Clear or extend the schedule to continue, and keep Fetchrail running, including in the tray, for scheduled starts. Check total and per-download speed limits if a resumed transfer is slower than expected.

Before asking for help

Check that the file still exists on the server, the destination has space and the partial files are present. Include the app version, operating system and a non-private example URL in an issue. The user guide and architecture guide describe the behavior in more detail.
