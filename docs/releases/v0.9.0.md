Fetchrail 0.9.0 expands desktop download sources, makes link recovery and browser capture easier, and adds explicitly opt-in discovery workflows. The release keeps verification and user confirmation as the boundary between discovering a link and saving a file.

## More ways to download

- **FTP, FTPS, FTPES, and SFTP:** direct desktop transfers, with standard SSH host-key verification for SFTP and certificate validation for TLS. Reduce redundant FTP commands and use bounded SFTP read-ahead to improve performance on suitable connections. These transports retain checksum checks and do not silently use the HTTP proxy.
- **Verified HTTP mirrors:** optionally supply one primary address and up to seven alternate HTTP(S) links. Fetchrail checks the advertised size, ranges, and validators independently for each source; retries can switch sources. A trusted SHA-256 is required, and the entire file must match it before publication. Mirrors are not guaranteed to outperform a single server.
- **Metalink 4 (.meta4):** import a local single-file manifest to review its filename, size, SHA-256 and up to eight HTTP(S) sources in the ordinary add-download dialog. Importing never automatically starts a transfer, and the manifest must come from a trusted publisher.

## Recovery and download management

- **Expired download links:** update a paused or failed transfer's source. When a trusted expected SHA-256 is supplied, opt into reusing previously verified parts after source and range checks. Unproven bytes are never silently stitched into a replacement file.
- **Browser interception:** define per-site and file-type capture exclusions and minimum-size rules, without changing manual browser handoffs. Optional clipboard-link suggestions keep explicit download confirmation.
- **Queues:** set recurring weekly start/stop windows and download priorities with aging to reduce starvation. Existing per-download and global speed limits remain in force.
- **Network routing:** configure a fail-closed HTTP or SOCKS5 proxy with remote DNS for native HTTP(S) downloads, plus per-site request budgets. Changing a proxy requires a full application restart; torrents and FTP/SFTP keep their own transport rules.

## File handling and automation

- **ZIP extraction:** extract completed ZIP downloads manually or opt into extraction of future downloads. Unsafe paths, duplicates, symlinks, encrypted entries and decompression abuse are rejected, and the original archive is retained.
- **RSS/Atom subscriptions and watched folders:** discover enclosure or local link-list/torrent candidates in user-approved sources. Newly discovered items enter a review queue; no downloads or torrent seeding start without confirmation. Feed requests reject private network targets and restrict redirects, while folder scanning remains nonrecursive and does not modify watched files.

## Platform scope and limitations

Windows x64 and Linux x64/ARM64 remain the signed desktop distribution targets. The separate **Fetchrail Android v0.1.0 developer preview** offers basic HTTP(S) downloads and Android sharing, but is not feature-equivalent to the desktop app or bundled as a desktop release asset.

This version does **not** include the unfinished HLS/DASH downloader, a remote web dashboard, automated file-host plugins, RAR/7z extraction, or unattended RSS/torrent downloading. It does not bypass DRM, CAPTCHA or private-site authentication. Some source-specific behaviors and system-managed storage or network limitations still require real-device testing.

Store publishing and review are separate from signed desktop release publication. A store may take additional time to approve an extension update.
