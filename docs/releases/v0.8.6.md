Fetchrail 0.8.6 carries forward the browser companion reliability and concurrent-download improvements prepared in earlier release candidates, with corrected Linux and Windows release qualification for the current browser handoff protocol.

## Browser companion

- Improve independent handling of simultaneous browser downloads in Chromium and Firefox, including filenames, private-session details, recovery and safe browser fallback.
- Verify a replayable full GET before browser ownership changes, retain that response, and consume its bytes once on the native transfer.
- Preserve browser prompt approval: intercepted click-monitor downloads stay paused until the user chooses to start them.

## Release qualification

- Match integration assertions to the single connection used for a retained browser GET, and verify normal, private and authenticated Chromium/Firefox handoffs against the native engine.
- Verify that malformed HTTP byte ranges cannot corrupt ordinary parallel downloads, while a valid full GET remains usable for captured browser transfers.
- Resume the click-monitor test transfer after checking its intentionally paused prompt state; the test then verifies its SHA-256 and absence of redundant network requests.

The earlier release tags are retained unchanged. Store submission is gated on a successfully qualified signed desktop release; Chrome Web Store review and rollout are controlled by Google.
