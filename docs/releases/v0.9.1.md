Fetchrail 0.9.1 improves browser capture of generated files and avoids redundant native-companion readiness checks when the desktop app is starting. Downloads remain in the browser whenever a safe handoff cannot be verified.

## Browser download capture

- **ChatGPT-generated files:** Chromium and Firefox companions can associate supported temporary `blob:` downloads with an observed completed HTTPS file request. The original source must match the tab, filename, timing and private or container scope unambiguously. Fetchrail verifies the native transfer before cancelling the browser download; unmatched, failed and already-completed browser files remain in the browser.
- **Desktop startup:** Concurrent captured downloads now share a single in-flight companion readiness probe while Fetchrail is starting, avoiding duplicate native-host checks.
- **Authenticated downloads:** Session-header forwarding stays opt-in through **Use browser session for captured files**. Signed file URLs are not persisted without that preference, and captures continue to respect site and file-type exclusions.

## Compatibility and limitations

This update covers the Windows x64 and Linux x64/ARM64 desktop app and the Chromium/Firefox browser companions. The Android developer preview has a separate release lifecycle.

The new ChatGPT-specific handoff has been verified with automated browser-request and fallback fixtures; it has not yet been qualified against an actual signed-in ChatGPT file download in an installed browser. Unsupported sources and changed site endpoints may continue downloading through the browser. Store submission and approval occur separately from publication of the signed desktop builds.
