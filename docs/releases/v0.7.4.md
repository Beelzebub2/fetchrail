Fetchrail 0.7.4 improves large-download recovery, adds a redesigned browser companion and gives the desktop app more appearance and progress controls. This release includes the changes since the last published stable release, v0.6.1.

## Highlights

- Large validated downloads use a finer bounded range queue and up to four independent HTTP client pools, while keeping the configured connection, bandwidth and origin limits.
- Slow ranges can renew a verified remaining suffix after a transport error or a degraded replacement, within the existing three-attempt budget. Resume keeps the original range boundaries and verified bytes.
- The redesigned browser companion includes page batches, transfer controls, connection choices and matching desktop accents. Both bundled browser builds now include the accent script they load.
- Desktop appearance includes a custom accent picker and a smaller download progress window, with clearer receiving and connection progress.
- Windows file handling retains content verification, internet-zone provenance, protected publication and durable history. Attachment checking remains enabled by default; its optional opt-out does not change Windows Defender settings.

## Performance and integrity

Controlled slow-range tests and complete-file downloads verify the recovery changes, output hashes, durable catalogs and connection ceilings. Favorable large-file runs reached approximately 113 MB/s; later production verification averaged approximately 91 MB/s while independent network controls also measured lower delivery rates. A sustained 100–110 MB/s is not guaranteed. Source behavior, network conditions and Windows attachment processing still affect completion time.

Existing download history, settings, queues and partial transfers remain compatible. Windows attachment checking and all integrity checks stay enabled unless the user explicitly changes the corresponding setting.

## Downloads and browser companions

Choose the Windows x64 setup, or a Linux x64/ARM64 AppImage, DEB, RPM or native archive. `SHA256SUMS` covers the release downloads; `release-metadata.tar.gz` contains signatures, dependency inventories, notices and the Arch recipe. `latest.json` carries the signed updater metadata.

The desktop setup includes the native host and manual companion packages. Browser store submissions follow desktop publication; submission and store approval are separate steps. Existing signed local Firefox companions remain compatible with the native host and can use the improved desktop engine.
