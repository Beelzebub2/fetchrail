Fetchrail 0.8.3 updates the Chrome and Firefox browser companions with reliability and concurrent-download fixes added after v0.8.2. The Chromium package is submitted to the Chrome Web Store after the desktop release passes the existing signed-package checks; store approval and installation follow the store's own process.

## Browser companion fixes

- Keep concurrent browser download captures independent while the native host starts, including Chromium filename decisions and Firefox request context recovery.
- Group accepted downloads into one native confirmation dialog while retaining per-file names, settings, late arrivals, and retryable failures. Dismissing a later prompt does not cancel downloads already started.
- Improve extension capture recovery, cancellation, status handling, and browser panel feedback while preserving safe fallback to the browser when a handoff cannot be completed.

## Validation and limits

Automated browser, routing, batch, handoff, reliability, and store-package checks cover the changed extension paths. The preceding PRs also verified a three-download real Chromium normal-mode burst with exact bytes and no duplicate browser transfers. Chromium private-mode capture and a clean repeated Firefox temporary-add-on burst were not fully qualified in those PRs; this release does not imply that those paths have been independently proven on every supported browser.

No browser permission expansion or new extension telemetry is introduced by this release. The existing extension/native-host registration and desktop data are retained.
