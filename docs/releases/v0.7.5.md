Fetchrail 0.7.5 adds private download troubleshooting and the separately scoped reliability analytics engine. It also includes the interface improvements and persisted torrent-metadata fixture correction made since v0.7.4.

This is a release candidate. Expanded remote reliability collection remains disabled while the final legal notice, hosting configuration and opt-in canary are awaiting approval. No release publication is implied by this file.

## Download troubleshooting

- The progress window has a Troubleshoot tab with a bounded local flight recorder. It separates receiving, retries, intentional limits, writes, verification, attachment processing, publication and saved history.
- Reports distinguish measured observations from unknown causes. Received HTTP body bytes, checkpoint bytes and verified durable completion have different meanings; concurrent worker times are not added into a false wall-clock total.
- Imports and browser verification/commit failures have their own local reports, including failures before a download exists. They never count as admitted fleet downloads.
- Torrent diagnostics expose safe numeric piece, file and checkpoint observations. Selected-ready remains distinct from HTTP durable completion.
- Optional protected crash breadcrumbs are separately off by default, limited to 20 reports/seven days, with inspection and deletion. Unsaved evidence can be lost in a crash.
- Incident JSON requires a preview and explicit review before copying or exporting. There is no automatic incident upload.

## Privacy and analytics

Existing improvement consent remains unchanged and never enables the new reliability purpose. The new scope uses a separate fresh choice, memory-only batches, fixed counters and coarse duration distributions. It excludes URLs, filenames, paths, credentials, raw messages and persistent user/device/transfer identifiers. Declining either purpose changes no download functionality.

The private operator readout preserves release/OS/architecture groups and sample limits. Public intake cannot establish unique users or representative failure rates. Cloudflare sees transport metadata; these controls do not establish absolute anonymity, EU-only processing or regulatory certification.

Existing installation identity, download history, browser integration, integrity checks and publication protections are preserved. Controlled test results do not guarantee throughput or identify internal causes in every server, network, storage device or antivirus service.

## Downloads and browser companions

The planned packages retain Windows x64 setup and Linux x64/ARM64 AppImage, DEB, RPM and native archives, with the existing signature/hash verification and updater metadata. Browser store submission and store approval remain separate steps.
