Fetchrail 0.8.7 delivers the Chromium and Firefox companion updates prepared in previous release candidates and fixes restart recovery for authenticated browser handoffs on Linux.

## Browser companion

- Improve capture reliability and concurrent download handoffs while preserving filenames, private browser sessions, native confirmation and safe fallback to the browser.
- Consume one verified full GET without issuing a second request, including when servers do not support valid byte ranges.
- On Linux, leave an interrupted browser-authenticated download paused after app restart because its temporary credentials and verified response are intentionally not persisted. The browser can reauthorize it without an automatic unauthenticated retry.
- Preserve Windows recovery using protected, restorable request credentials when an activation remains pending across restart.
- Keep Firefox private and container captures in the app when download events arrive before their matching session headers.

## Release qualification

- Verify Windows activation retry, Linux reauthorization after restart, and protected credential storage with real native companion fixtures.
- Exercise Chromium/Firefox normal, private and authenticated captures, exact SHA-256 output, resume, cancellation, recovery, and full-GET validation in Linux and Windows CI.
- Preserve ordinary parallel-transfer rejection of invalid `Content-Range` responses while accepting a verified browser full GET.
- Use the explicitly supplied torrent fixture helper for installed packages, fail promptly if it is missing, and reserve activation fault injection for test-enabled app builds.

Chrome Web Store submission remains gated on the fully qualified signed desktop release. Store review and rollout are controlled by Google. Earlier release tags remain immutable.
