# Reliability measurement catalogue (scope 3)

Owner: Fetchrail engineering / RRMTools. The [processing review](reliability-privacy-review.md) records the operator's prior decisions; the [v3 delivery contract](reliability-v3-delivery.md) records the October 21 changes and remaining validation. Native `REMOTE_RELEASE_APPROVED` is true. Worker intake needs both `QUALITY_ANALYTICS_ENABLED` and `QUALITY_V3_ANALYTICS_ENABLED` to equal `"true"`; the v3 gate is false in checked-in configuration for staged receiver rollout. The new notice is `reliability-v3-20261021`. These source values describe implementation, not proof of live deployment.

Current optional remote fields use **product-quality-v3**, schema 3. Earlier improvement or v2 grants cannot activate them. Values accumulate only for newly durably admitted tasks in the current consent epoch, and checkpoint into a separately consented bounded private outbox. No restored/history/pre-consent task joins later. Each eligible logical transfer contributes one first terminal outcome; a retry or source replacement does not create another logical acceptance. Admission and outcomes can fall in different batches/days. Never divide a day's completions by that day's admissions to estimate completion probability. Legacy v2 receiver rows and histogram meanings remain separate and unchanged.

## Envelope, scope and storage

| Field | Definition / source | Decision and denominator | Retention / test |
| --- | --- | --- | --- |
| `schema`, `purpose` | Constants `3`, `product-quality-v3` | Refuse incompatible meanings, no v1/v2 blending | Private outbox ≤7 days; 30 receipt-day aggregates; native golden and Worker mismatch tests |
| `version` | Public stable Cargo release version; three numeric components, no build hash or prerelease | Compare releases using the same scope/definitions | Same; native fixture + Worker semver tests |
| `os`, `arch` | `windows/linux/other`, `x64/arm64/other` | Broad platform interoperability, never hardware identity | Same; closed-vocabulary tests |
| `counters` | Finite keys below, integers 1–1000; saturation sets `clipped:1` | Counts of observations, never people/sessions | Same; lifecycle/epoch/randomized/overflow tests |
| `histograms` | Finite keys below; eight worker/stall bins or fifteen v3 HTTP duration/rate bins, integers 0–1000 | Merge distributions rather than average client percentiles | Same; shared golden, malformed bins, merge and quantile tests |
| `batchId` | Random 32-hex nonce for one immutable batch, renewed for each batch | A retry ACK must match this nonce; no user/device/session/transfer linkage | Native queue ≤7 days; server nonce/hash/expiry receipts 8 days, plus provider recovery history |
| `provenance` | `controlled` in test-tools; `production` in ordinary builds | Keep declared QA and production distributions separate; this cannot authenticate anonymous callers | Separate v3 aggregate dimension; old rows remain unclassified |

The affirmative decision, decision time and notice revision remain device-local consent evidence. No exact client timestamps, local transfer IDs, origins/host hashes, endpoints, paths, names, headers, arbitrary errors, payload bytes, infohashes, trackers, peers, models, fingerprints or persistent caller identifiers are accepted remotely. SQLite stores daily preaggregates, eight-day nonce/hash/expiry receipts and daily ingestion counters, never raw envelopes. Cloudflare still processes IP/transport metadata; no anonymity or EU-only-processing claim.

Server receipt day is UTC; the client cannot choose it. The readout includes the server generation time and exact retained receipt-day window. V3 dimensions are day/release/broad OS/arch/provenance, with **64 total groups/day across all three schemas**, not a cause × size × server cross-product. Native v3 payloads are at most 8192 bytes (v2 remains 4096; v1 remains 2048). Intake cannot prove consent or caller authenticity; immutable retries deduplicate only while their eight-day receipt remains. Quality groups below **5 report batches** are suppressed. Five batches do not mean five people. p50 needs 5 observations and p95 needs 20; both return bucket upper bounds with units. Overflow has no finite bound. Clipped rows cannot support precise rates.

## Histograms and clocks

Durations use monotonic `Instant`, measured in milliseconds. Worker/stall inclusive upper bounds remain **10, 100, 1000, 10000, 60000, 300000, 1800000**, followed by overflow. Histogram suffixes version definitions independently of envelope schema; v3 never reinterprets old eight-bin HTTP observations.

`http_e2e_{size}_ms_v2` records one accept-operation-to-durable-catalog duration for a fully observed HTTP completion. Inclusive bounds are **1000, 5000, 10000, 30000, 60000, 90000, 120000, 150000, 180000, 210000, 240000, 300000, 600000, 1800000** ms, then overflow. The clock starts with the new task before initial catalog admission; failed admission never registers. It includes queue, deliberate scheduling/pause, backoff and finalization. It is **not active-only duration**. Incomplete coverage contributes `e2e_unobserved`. Restored tasks remain wholly ineligible; failed/cancelled/torrent outcomes are not HTTP completion-time samples.

`http_delivery_{size}_mbps_v1` records new observed HTTP body bytes divided by cumulative time in the `Transferring` lifecycle state, including client processing, in-range retries and configured limits. Queue, paused, separately scheduled/backoff and finalization lifecycle states are outside this denominator; the end-to-end metric includes them. It excludes previously resumed bytes and metadata/TCP/TLS overhead and cannot identify link capacity. The cumulative denominator survives lifecycle-ring eviction; missing or zero duration contributes `throughput_unobserved`. Inclusive rate bounds in **decimal MB/s** are **1, 5, 10, 20, 40, 60, 80, 100, 110, 120, 140, 180, 250, 500**, then overflow. Native bucketing uses bytes per second; exact bytes and rates do not leave the device.

Both v3 HTTP histograms use `{size}` = `unknown`, `under10m` (<10 MiB), `10m1g` (<1 GiB), `1g4g` (<4 GiB), `4g16g` (<16 GiB), `16g64g` (<64 GiB), or `over64g` (≥64 GiB). Adjacent bands begin at the previous bound. Older `http_e2e_{unknown,small,medium,large}_ms_v1` remains a v2-only definition. Do not combine their samples.

`{probe,origin,global,headers,body_wait,limiter,write,flush,sync,checkpoint,retry,assembly,attachment,verify,journal,publish,catalog,scan_overlap}_worker_ms_v1` records the measured cumulative worker duration for that boundary per terminal transfer, only when the stage was actually called and has no remaining active spans. A saved cancellation can precede worker drain: unfinished durations are omitted, never fabricated zeroes. Concurrent spans and enclosing stages overlap. These are neither wall-clock shares nor additive critical-path time. An absent stage is unobserved, not zero. Owner/decision: engine maintainer compares stages to pick a focused fixture/profiler. Source: production-safe `transfer_span` and audited native boundaries. Tests: stage guards, concurrency, real HTTP/IO/finalization, golden serializer and full-app assertions.

The added `PrefixHash`, `DispatchLock` and `CatalogLock` phases remain **local-only**. They appear in bounded local health/export evidence but have no `stage_key` mapping and no accepted remote histogram key. The remote stage list above is deliberately unchanged; the presence of a new local timing phase does not silently expand the reliability schema.

`stall_total_ms_v1` records cumulative qualified no-progress duration for transfers with observed receive stalls. The progress sampler reuses the existing 180 ms cadence. Body-delivery windows and exact numeric byte/cap/peer observations remain local; no window sequence or exact byte values enter either quality schema. Recent windows normally span five to six seconds. Longer sampling intervals retain their actual bytes/duration and increment the delayed-sampling count; they cannot establish uninterrupted detailed coverage. Their rate includes client processing and wait, so it is not mislabeled pure active-network throughput.

## Local-only evidence and unknowns

The local report includes at most 64 boundary events, 64 lifecycle transitions, 120 recent delivery windows and 64 compressed older windows. Older windows are pairwise combined with their bytes and durations preserved; they retain whole-run volume/time at lower temporal resolution. The separate cumulative transfer clock survives lifecycle-ring eviction. Up to 32 policy changes and 32 retry-cost records are retained, alongside fixed phase/cause arrays and scalar counters. Long completed stage calls (≥100 ms), finalization boundaries and categorized causes and numeric range/attempt summaries enter the pre-incident ring; routine events cannot erase every retained failure/retry. Snapshots order intervals by monotonic start time and retain duration; overlapping intervals remain explicit. Active spans show current elapsed time. Eviction, delayed sampling, absent spans and pre-restart coverage are explicit. Total transfer lifecycle is a neutral activity observation, not proof of receive waiting or a source/route cause. Local JSON exports allow up to 128 KiB and validate all array bounds before saving.

Local `configuredCapObserved` records whether a positive configured file/global cap was seen since the recorder began or was explicitly cleared. It survives policy-ring eviction and resets on clear; older local reports deserialize it as false. Snapshot `fileLimitBps` / `globalLimitBps` come from the last retained policy, or remain unknown when no policy was observed. The interactive download-health command may refresh those two current values from present settings. Neither a configured cap nor a current setting alone proves it bound delivery; exact values and policy history remain local.

HTTP `receivedWireBytes` is actual delivered HTTP **body** bytes from new chunks, excluding metadata/TCP/TLS overhead and previously resumed bytes. `checkpointBytesWritten` counts newly committed checkpoint deltas after flush/sync/checkpoint save; it is not unique verified output. `outputVerifiedBytes` exists only at acknowledged HTTP completion. Retransferred/unique verified byte accounting not established by these observations stays unobserved.

Torrent native payload/failed/redundant byte counters reset on pause/restart, as documented by the pinned libtorrent 2.1.2 headers. Alert counters cover the current native job in the current process. The safe snapshot contains numeric counts and booleans only. Raw native activity, messages, paths, trackers and peer addresses remain excluded. Missing native schema fails to an unavailable snapshot, never fabricated zeroes.

Pre-admission reports use the fixed local contexts `browserVerification`, `browserCommit` and `torrentImport`; transfer reports use `transfer`. They are capped at 20 session operations and excluded from fleet transfer outcomes. Old local reports without this field retain transfer context. These context labels and operation reports are never added to remote payloads.

Optional crash history uses existing Windows DPAPI/private atomic file patterns, maximum 20 reports / seven days, one checkpoint per 30 seconds, also capped at 512 KiB by evicting oldest cases, no backup generation. It is off without a separate saved local choice. Clear removes stored history and invalidates old volatile coverage so it is not silently resaved. A hard exit loses unsaved evidence; a stored snapshot cannot prove later completion. Manually exported reviewed JSON is a separate file retained until its owner deletes it.
