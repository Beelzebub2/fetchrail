# Reliability measurement catalogue (draft scope 2)

Owner: Fetchrail engineering / RRMTools; legal-controller identity remains an owner decision in [processing review](reliability-privacy-review.md). This is the finite implementation catalogue, not authorization to activate collection. Native `REMOTE_RELEASE_APPROVED` is false; Worker `QUALITY_ANALYTICS_ENABLED` must explicitly equal `"true"`. Approval must replace `NOTICE_REVISION` so draft choices do not silently become production permission.

All optional remote fields below use **product-quality-v2**, schema 2. A legacy product-improvement-v1 grant cannot activate them. Values accumulate in RAM only for newly durably admitted tasks in the current consent epoch. No restored/history/pre-consent task joins later. Each eligible logical transfer contributes one first terminal outcome; a retry or source replacement does not create another v2 logical acceptance. API admission and terminal outcomes can fall in different batches/days. Never divide a day's completions by that day's admissions to estimate completion probability.

## Envelope, scope and storage

| Field | Definition / source | Decision and denominator | Retention / test |
| --- | --- | --- | --- |
| `schema`, `purpose` | Constants `2`, `product-quality-v2` | Refuse incompatible meanings, no v1 blending | RAM; 30 receipt-day aggregates; native golden and Worker mismatch tests |
| `version` | Public stable Cargo release version; three numeric components, no build hash or prerelease | Compare releases using the same scope/definitions | Same; native fixture + Worker semver tests |
| `os`, `arch` | `windows/linux/other`, `x64/arm64/other` | Broad platform interoperability, never hardware identity | Same; closed-vocabulary tests |
| `counters` | Finite keys below, integers 1–1000; saturation sets `clipped:1` | Counts of observations, never people/sessions | Same; lifecycle/epoch/randomized/overflow tests |
| `histograms` | Finite keys below; exactly eight integer buckets 0–1000 each | Merge distributions rather than average client percentiles | Same; shared golden, malformed bins, merge and quantile tests |

Native purpose/schema/notice revision/affirmative decision/time/app version remain device-local consent evidence. None is uploaded except fixed purpose/schema and public release. No exact client timestamps, local transfer IDs, origins/host hashes, endpoints, paths, names, headers, arbitrary errors, payload bytes, infohashes, trackers, peers, models, fingerprints or persistent identifiers are accepted remotely. SQLite receives only daily preaggregates, never raw envelopes. Cloudflare still processes IP/transport metadata; no anonymity or EU-only-processing claim.

Server receipt day is UTC; the client cannot choose it. Dimensions are day/release/broad OS/arch, with **64 total groups/day across both schemas**, not a cause × size × server cross-product. Routine native payloads are at most 4096 bytes (legacy v1 remains 2048). Intake is public and cannot prove consent, authenticity or deduplicate callers. The protected readout suppresses v2 groups below **5 report batches**, not five people. p50 needs 5 samples; p95 needs 20, and returns a bucket upper bound. Overflow has no finite bound. Clipped rows cannot support precise rates.

## Histograms and clocks

All durations use monotonic `Instant`, measured in milliseconds. Inclusive upper bounds are **10, 100, 1000, 10000, 60000, 300000, 1800000**, followed by overflow. Histogram suffix `_v1` versions these definitions independently of envelope schema.

`http_e2e_{unknown,small,medium,large}_ms_v1` records one accept-operation-to-durable-catalog duration for a fully observed HTTP completion. The clock starts with the new task before its initial catalog admission; failed admission never registers. It includes queue, deliberate scheduling/pause, backoff and finalization. It is **not active-only duration**. Cleared incomplete coverage contributes `e2e_unobserved`, not an invented zero or reconstructed duration. Restored tasks remain wholly ineligible; failed/cancelled/torrent outcomes are not HTTP completion-time samples.

`{probe,origin,global,headers,body_wait,limiter,write,flush,sync,checkpoint,retry,assembly,attachment,verify,journal,publish,catalog,scan_overlap}_worker_ms_v1` records the measured cumulative worker duration for that boundary per terminal transfer, only when the stage was actually called and has no remaining active spans. A saved cancellation can precede worker drain: unfinished durations are omitted, never fabricated zeroes. Concurrent spans and enclosing stages overlap. These are neither wall-clock shares nor additive critical-path time. An absent stage is unobserved, not zero. Owner/decision: engine maintainer compares stages to pick a focused fixture/profiler. Source: production-safe `transfer_span` and audited native boundaries. Tests: stage guards, concurrency, real HTTP/IO/finalization, golden serializer and full-app assertions.

`stall_total_ms_v1` records cumulative qualified no-progress duration for transfers with observed receive stalls. The progress sampler reuses the existing 180 ms cadence. Five-second body-delivery windows and exact numeric byte/cap/peer observations remain local; no window sequence or exact byte values enter v2. Windows longer than six seconds are marked missing. Their rate includes client processing and wait, so it is not mislabeled pure active-network throughput.

## Local-only evidence and unknowns

The local report includes at most 64 boundary events, 64 lifecycle transitions and 120 full delivery windows, fixed phase/cause arrays and scalar counters. Long completed stage calls (≥100 ms), finalization boundaries and categorized causes and numeric range/attempt summaries enter the pre-incident ring. Snapshots order intervals by monotonic start time and retain duration; overlapping intervals remain explicit. Active spans show current elapsed time. Eviction, missing windows, absent spans and pre-restart coverage are explicit. Stage durations do not expose external internals; the diagnosis names an observed boundary/category and the next diagnostic rather than claiming an ISP, server or antivirus root cause.

HTTP `receivedWireBytes` is actual delivered HTTP **body** bytes from new chunks, excluding metadata/TCP/TLS overhead and previously resumed bytes. `checkpointBytesWritten` counts newly committed checkpoint deltas after flush/sync/checkpoint save; it is not unique verified output. `outputVerifiedBytes` exists only at acknowledged HTTP completion. Retransferred/unique verified byte accounting not established by these observations stays unobserved.

Torrent native payload/failed/redundant byte counters reset on pause/restart, as documented by the pinned libtorrent 2.1.2 headers. Alert counters cover the current native job in the current process. The safe snapshot contains numeric counts and booleans only. Raw native activity, messages, paths, trackers and peer addresses remain excluded. Missing native schema fails to an unavailable snapshot, never fabricated zeroes.

Pre-admission reports use the fixed local contexts `browserVerification`, `browserCommit` and `torrentImport`; transfer reports use `transfer`. They are capped at 20 session operations and excluded from fleet transfer outcomes. Old local reports without this field retain transfer context. These context labels and operation reports are never added to remote payloads.

Optional crash history uses existing Windows DPAPI/private atomic file patterns, maximum 20 reports / seven days, one checkpoint per 30 seconds, also capped at 512 KiB by evicting oldest cases, no backup generation. It is off without a separate saved local choice. Clear removes stored history and invalidates old volatile coverage so it is not silently resaved. A hard exit loses unsaved evidence; a stored snapshot cannot prove later completion. Manually exported reviewed JSON is a separate file retained until its owner deletes it.
